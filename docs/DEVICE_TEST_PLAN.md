# DEVICE_TEST_PLAN.md — 실기기(iPhone 13 Pro, LiDAR) 첫 시험 절차

목표: 합성·시뮬레이터로 검증한 것 중 **실기기에서만 확인되는 것**을 가려내고, 문제가 생기면 로그로 바로 원인을 가른다.
준비 상태(2026-10-11 점검): 서버 정상(8111, 외부 주소 `https://markerless.wizbase.ai.kr` 200, API 키 인증 동작), Mac LAN IP `192.168.2.105`(en1)가 앱 기본 주소와 일치, DB·저장소 백업 완료(`backups/`), 시뮬레이터 실행 시 크래시 없음.

## 0. 시작 전 (5분)
1. 폰 잠금 해제·같은 Wi-Fi. `tools/ios_install.sh "iPhone 13 Pro"` → 앱 왼쪽 위 빌드 번호가 출력된 번호와 같은지 확인 (잠겨 있으면 설치 후 직접 앱 실행).
2. 관리자 웹(`/admin/`)에 로그인 → **비밀번호 변경 화면**이 먼저 뜬다(기본 비밀번호는 이제 강제 변경). 10자 이상·3종 혼합.
3. 별도 터미널: `make devlog` (또는 `tools/devloop.sh`)로 서버·앱 로그 실시간. 앱 로그는 `backend/logs/dev.log`에 모인다. 오류만: `grep '"lvl": "ERROR"' backend/logs/dev.log | tail`.
4. 줄자/레이저 거리계 준비 — 방 폭·길이·층고·문 폭 4가지는 **먼저 재 둔다**(스캔 결과와 비교).

## 1. 회귀 시험 (기존 기능, 15분) — 먼저
| # | 절차 | 기대 | 실패 시 |
|---|---|---|---|
| 1-1 | 홈 → 공간 선택 → ③ 사물 외관 스캔 → 저장 | 저장 성공, 자산 목록에 보임 | `dev.log`의 `/assets/scan` 오류 |
| 1-2 | ③ 검수 → 같은 사물 조준 측정 | 윤곽선이 사물에 맞음, 판정 표시 | 윤곽 어긋남은 사물이 옮겨졌는지 먼저 확인 |
| 1-3 | **검수 → 스캔 탭 전환을 3회 반복** | 스캔 화면 카메라가 **굳지 않음**(이전 버그 수정 확인) | 로그 "카메라 프레임 없음 — 세션 재개" 가 뜨면 워치독이 복구한 것, 굳으면 보고 |
| 1-4 | 관리자 웹 검수 이력·자산 3D | 방금 측정이 보임 | |

## 2. 공간 전체 스캔 (핵심, 30분)
준비: 작은 방 하나(가구 몇 개), 조명 밝게, 사람은 가급적 없게.
1. ② 스캔·등록 → 상단 `① 공간 전체`. LiDAR 없는 기기면 시작 버튼이 막힌다(정상).
2. (선택) **구조 스캔(RoomPlan)** 먼저 1회 — 방 한 바퀴. 끝나면 "구조 저장".
3. **RGB-D 촬영**: 방 중앙에서 시작 → 벽을 따라 천천히 한 바퀴 → 천장·바닥·코너 → **출발점으로 돌아와 겹치게**(루프 클로저). 약 3~5분. HUD의 품질 알약(흔들림 비율·깊이 신뢰도)과 어시스트 문구를 따른다. 흔들림 경고가 뜨면 천천히.
4. "촬영 완료" → 업로드 진행 막대 → 서버 상태 `PROCESSING → READY`(보통 1~3분). `NEED_MORE_CAPTURE`면 안내 문구대로 추가 촬영.
5. 관리자 웹 → 자산 → **3D 디지털 트윈**: 재구성이 끝나면 방이 **"미배정 건물 (자동)" 1층에 임시 배치**되어 바로 보인다(위치는 임의 — 여러 방은 옆으로 일렬, 검토 필요 표시). 실제 건물 구성은 `PUT /api/v1/spaces/{id}/placement`로 지정. 모든 방이 같은 건물에 있어야 외피·내벽 두께가 만들어진다.

## 2-B. 스캔 품질 모니터링 UI 확인 (이번 신규 — `mobile-ios/SCAN_QUALITY_UI.md`)
공간 스캔 중 아래를 일부러 만들어 보며 UI가 맞게 반응하는지 본다.
| 시험 | 기대 |
|---|---|
| 천천히 방 한 바퀴 | 벽 링 칸이 순서대로 초록으로 채워지고 가볍게 진동. 쐐기가 시선을 따라 회전 |
| 일부러 빠르게 휘두르기 | 품질 바가 주의/나쁨 + "너무 빠름", 경고 진동, 그 구간 칸은 안 채워지거나 주황 |
| 벽에 바짝 붙기 / 멀리 떨어지기 | "너무 가까움/너무 멂" 이유와 행동 안내, 거리 m 표시 |
| 손으로 렌즈 가리기·어두운 곳 | 깊이 불확실/어두움 이유 |
| 한쪽 벽을 건너뛰고 한 바퀴 | 빠진 벽 구간이 빨강으로 남고 화면 가장자리에 화살표+각도 |
| 천장·바닥 무시 | 위/아래 안내 화살표 |
| [촬영 완료] (빈 곳 있음) | 점검 화면(지도+목록). [부족한 곳 다시 스캔] → 목표 칸 맥박 → 채우면 "채워졌어요" |
| [그대로 진행] | 기존대로 업로드 |
| 사물 스캔(③) | 둘레 링이 채워지고 "뒷면·왼쪽 면 비어 있음" 점검, 윗면 안내 |
기록할 것: 점검 화면이 **너무 자주/너무 드물게** 뜨는지, 칸이 너무 쉽게/어렵게 채워지는지, 화살표 방향이 맞는지(좌우 반대면 보고), 발열·프레임, 진동 느낌. 앱 로그 태그 `space-scan`/`scan`에 종료 시 요약 한 줄이 남는다(링별 %, 문제 수, 평균 품질).

## 3. 규약·정렬 확인 (실기기에서만 가능한 것)
- **픽셀 규약 A/B** (반픽셀): 위 스캔 세션 ID로 `.venv/bin/python tools/pixel_ab.py <scanSessionId>` → 두 규약의 벽 층 번짐 비교. 권장이 `0`이면 서버를 `MARKERLESS_PIXEL_OFFSET=0`으로 재시작(`Makefile api` 타깃에 환경변수 추가). 차이가 작다고 나오면 기본값 유지. (합성 데이터에선 차이가 거의 없었음 — 영향은 작을 것으로 예상)
- **RoomPlan 정렬**: 재구성 리포트(`/admin/api/twin/spaces/{ref}/sessions` 또는 DB `mesh_revisions.stats`)의 `notes`에 "RoomPlan 구조를 메시에 정렬해 사용" 또는 "정렬 실패(모호/잔차)"가 남는다. 직사각형 방 + 문·창 단서 없음이면 모호 판정이 정상.
- **월드맵 재위치**: 같은 방을 두 번째 스캔 → `registered=true`(재위치 성공)인지. 실패(UNREGISTERED)면 자동 병합이 거절되는 것이 정상.
- **LiDAR 깊이 신뢰도**: 유리·거울·검은 장비 앞의 구멍 비율을 눈으로 기록.

## 4. 견고성 시험 (20분)
| 시험 | 기대 |
|---|---|
| 촬영 중 화면 잠금/전화 수신 → 복귀 | RECOVERY 상태 → 새 구간(segment)으로 이어서, 프레임 손실 없음 |
| 업로드 중 Wi-Fi 끄기 → 켜기 | 중단 후 **이어서** 업로드(offset 재개) |
| 앱 강제 종료 → 재실행 | 큐 복구, 미완료 세션 마무리 |
| 5분 연속 촬영 후 폰 온도 | `thermalState ≥ serious`면 자동 일시정지 + 메시지 |
| 방 안에서 사람이 지나가게 | 유령 없어야 함(AI 사람 마스크), 앱 "방금 구간 제외" 버튼 |
| 재구성 중 웹 접속 | 응답 지연 없음(부하 시험: p95 9ms) |

## 5. 웹 투어 (10분)
데스크톱 크롬 + 폰 브라우저: 외부 조망→출입문→걷기→포털, 레이어 토글(추정=주황, 미관측 강조), 품질 선택, 사진 모드. FPS·끊김 기록(헤드리스는 CPU 렌더라 실GPU 수치가 필요).

## 6. 통과 기준 (초안)
- 방 치수 오차 ≤ 2% 또는 ≤ 5cm, 커버리지 ≥ 85%(미관측 별도 표시), 벽 한 겹, 텍스처 심각 결함 0건, 유령 0건.
- 정렬·CAD 후보가 **모호하면 거부**하는지(잘못 확정 0건).
- 회귀 1-1~1-4 모두 정상.

## 7. 문제가 생기면 모아 둘 것
1. 앱 화면 스크린샷 + 앱 왼쪽 위 빌드 번호.
2. `backend/logs/dev.log` 해당 시각 ±2분 (`grep` 로 session/scan/recon 태그).
3. 스캔 세션 ID (앱 업로드 카드 또는 `/admin/api/twin/spaces/{ref}/sessions`).
4. 가능하면 같은 방 두 번째 스캔(재현성).
그러면 `tools/pixel_ab.py`·`tools/twin_bench.py`·재구성 리포트로 원인을 가른다. 재구성은 프레임 원본이 저장소에 보존되므로 **파라미터를 바꿔 같은 스캔을 다시 돌릴 수 있다**(`POST /scan-sessions/{id}/reconstruct`, `voxelM`, `textureMaxPx`).

## 8. 알려진 한계 (시험 전에 알아 둘 것)
- 미등록 사물이 등록 자산으로 **오확정**될 수 있다(기존 검수 자동 매칭, 합성 기준 ~60%). 공간 스캔의 자산 연결은 후보 제안만 한다. 검수 때 자동 매칭 결과는 반드시 눈으로 확인.
- 거울·유리 AI 마스크는 기본 꺼짐(경계 번짐). 큰 거울은 직접 확인.
- 투어 FPS·RoomPlan·열/메모리는 이번이 첫 실측이다. 임계값(선명도·정지·마스크)은 초기값이다.
