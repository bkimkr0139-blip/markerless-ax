# 마커리스 BIM·CAD 시공검수 PoC — 개발 내역서

> 이 문서는 지금까지 구현한 모든 메뉴·기능·특징을 정리하고, 마지막(§13~14)에서 **추가 고도화 과제**를 도출하도록 구성했다.
> 서비스 화면의 [시스템 설정 → 개발 내역서 다운로드]로 받을 때마다 맨 끝에 *현재 운영 현황*이 자동으로 붙는다.
> 코드 구조·수치는 작성 시점 기준이며, 정확한 최신 값은 소스와 `docs/` 폴더를 우선한다.

---

## 1. 제품 개요

| 항목 | 내용 |
|---|---|
| 목적 | 마커(QR 등) 없이 스마트폰만으로 현장 설비·사물의 **설계(등록) 위치·크기와 실제 상태를 비교**해 합격/불합격을 판정하는 시공검수 도구 |
| PoC 방식 | **자가 에셋 생성(Scan-to-BIM/CAD)**: 사물을 LiDAR로 스캔 → 3D 모델(GLB) 등록 → 같은 공간에서 재스캔해 매칭·편차 판정. 실제 Revit/CAD 패키지는 `POST /api/v1/packages`로 같은 테이블에 임포트 가능하게 설계 |
| 구성 요소 | ① iOS 앱(SwiftUI·ARKit·RealityKit) ② FastAPI 백엔드(SQLite) ③ `spatial-core`(numpy/scipy 정합·판정 엔진) ④ 통합관리자 웹(`/admin/`, 바닐라 JS) |
| 정합 엔진 위치 | 기기별 중복 구현 없이 **서버에서 공통 실행** (모바일은 캡처·오버레이 전담) |
| 서비스 주소 | `https://markerless.wizbase.ai.kr` (frp → nginx → 개발 Mac의 8111 포트) |
| 지원 기기 | LiDAR iPhone(13 Pro 이상)에서 최상. LiDAR가 없으면 카메라+IMU 특징점 모드로 동작(정확도 낮음) |

### 설계 원칙 (요약)
1. 첫 성공 경로는 iOS + LiDAR. 2. 좌표계는 명시적으로 관리(`docs/COORDINATE.md`). 3. 모든 Pose 결과에는 Confidence 포함.
4. 한 프레임으로 판정하지 않고 다중 프레임을 누적. 5. Ground Truth 없이 정확도를 주장하지 않음. 6. 자동 PASS는 HIGH 신뢰도만.
7. 테스트 우선, 판정 근거(reasons/margins)를 항상 저장.

```

├─ spatial-core/      정합(ICP)·판정·신뢰도·분리(segmentation)·외곽선 엔진 (순수 Python)

├─ docs/              DESIGN / COORDINATE / API / REPORT / DEVLOOP
```

## 3. iOS 앱 (현장 단말)

하단 탭 3개: **홈 · ② 스캔·등록 · ③ 검수**. 모든 화면 왼쪽 위에 빌드 번호(예: `261008.1830`)가 표시되어 설치본이 최신인지 한눈에 확인한다.

### 3.1 홈 (공간 선택·작업 시작)
- 서버 연결 상태, 프로젝트·공간 카드(자산 수·월드맵 유무), 공간 생성/선택, 서버 주소 설정.
- 선택한 공간이 이후 스캔·검수의 기준 좌표계가 된다. 관리자가 공간을 지우면 앱 선택도 자동으로 풀린다(이벤트 동기화).
- 최근 작업·바로가기가 있는 카드형 홈(세련된 홈 화면으로 개편됨).

### 3.2 ② 스캔·등록 (자산 만들기)
단계 안내 알약(1/5…5/5)이 현재 단계와 다음 행동을 알려 준다.
1. **조준**: 화면 중앙 십자선으로 사물 표면을 겨눈다. LiDAR는 깊이맵 중앙 표면, 비-LiDAR는 특징점 원뿔/메시 교차로 중심을 잡는다.
2. **대상 확정(POI)**: 중심에 3D 마커가 생기고 이후 깊이 누적은 그 주변(기본 반경 1.3m)만 사용.
3. **스캔**: 사물 둘레를 돌며 촬영. `DepthFusion`이 LiDAR 깊이를 격자 융합해 메시보다 촘촘한 안정 점을 만들고, `ScanCoverage`가 둘레 커버리지(방위 섹터)를 계산해 **어시스트 칩**("오른쪽 뒤를 더 비추세요" 등)과 햅틱으로 안내. 카메라가 너무 빠르면(0.5m/s, 57°/s) 점을 버리고 경고.
4. **검토(분리 확인)**: 서버 `/segment`로 바닥·벽·주변을 제거해 사물만 분리. 초록 **외곽선**, 보라 **외곽 박스**, 제도식 **치수선(mm)** 을 AR로 미리 보여 주고, 품질 평가(확보 면 n/4·점수·팁)를 표시. 범위 반경 조절·[더 스캔] 가능. 품질이 낮으면 "그래도 저장/더 스캔" 확인창.
5. **저장**: 자산 ID(자동 생성 또는 입력)·이름으로 GLB + 메타(`multipart`)를 서버에 올리고, 방향별 **사진 실루엣 카드**(키프레임을 흑백 실루엣으로 가공)와 **월드맵**을 함께 업로드. 같은 ID로 저장하면 이전 모델을 덮어쓴다(재등록).
- 저장 후: "새 사물 스캔"(추적 유지, 누적 데이터만 초기화) 또는 "③ 검수로 이동".
- 부가: GPS 위치 기록, 자산 관리 시트(목록·삭제·재등록), HUD 숨김(눈 버튼), 보정(캘리브레이션) 패널, 입력 키보드 처리.

### 3.3 ③ 검수 (현장 비교·판정)
- **월드맵 복원**(기본 켜짐): 등록 때의 공간 좌표로 세션을 시작해, 설계 위치에 모델 오버레이. 복원 성공(relocalized)을 확인해야 위치 편차 판정에 사용하며, 실패하면 일반 세션으로 진행.
- **자산 선택 방식**
  - *지정 검수*: 자산을 직접 골라 측정.
  - *자동 매칭*: 사물을 비추고 [조준 측정] → 서버가 후보 자산을 순위화해 자동 확정하거나 **후보 목록**(유사도·치수 차이)을 보여 주고 사용자가 선택.
- **측정**: 조준 사물 주변 LiDAR 점군(최소 점 수 충족 시)을 서버로 전송 → 서버 정합 → 결과 배너(합격/불합격/사람 확인/재측정, 편차 mm·°, 신뢰도, 근거).
- **AR 레이어** (자산별로 관리자 웹에서 기본값 지정, 앱에서 칩으로 토글): 모델 표면 · 점군 · **외곽선**(기본 켜짐) · 외곽 박스 · 치수 · 사진 실루엣 · 관측 외곽선(노란색, 외곽선 레이어를 켰을 때만).
- **추적 보정(`PoseRefiner`)**: 서버가 정한 자세를 기준으로, 기기에서 실시간 LiDAR 점을 모델에 4자유도(yaw+이동) point-to-plane 정합으로 따라가 외곽선이 사물에 붙어 있게 한다. 이동 10cm·회전 15° 게이트, 서버 자세로부터 15cm 상한. 재위치 인식(relocalization) 시 융합 데이터 리셋.
- **UI**: 하단 **아이콘 도크**(글자 대신 아이콘, 검정 캡션 알약, 햅틱), 후보 선택 체크 버튼, 레이어 아이콘 칩.
- 관리자가 자산을 수정하면 앱이 SSE 이벤트로 즉시 반영(`dataRevision`).

### 3.4 그 밖
- 앱 아이콘: "WML" 로고(Assets.xcassets/AppIcon).
- `DebugLog`: 앱 로그를 서버 `/api/v1/log`로 보내 `backend/logs/dev.log`에 쌓음(개발 폐루프).
- 두 화면(스캔/검수)은 각자 ARSession을 가지며, 화면 전환 시 카메라 소유권을 하나로 정리(최근 수정: 전환 후 카메라가 굳는 문제 방지 + 프레임 워치독).

## 4. 백엔드 API (모바일용 `/api/v1`)

모든 JSON은 camelCase, 좌표 m·각도 도(°)·편차 mm. 선택적으로 `MARKERLESS_API_KEY` 헤더 인증. 대화형 문서 `/docs`.

| 영역 | 엔드포인트 | 설명 |
|---|---|---|
| 상태 | `GET /healthz`, `/api/v1/version` | 헬스·버전 |
| 프로젝트·공간 | `/projects`, `/projects/{code}/spaces`, `/spaces/{id}` | 생성·조회, 미존재 프로젝트 자동 생성 |
| 월드맵 | `PUT/GET /spaces/{id}/worldmap` | 바이너리 + `X-Sha256` 검증, bplist 시그니처 검사 |
| 자산 | `POST /assets/scan`, `GET /spaces/{id}/assets`, `GET /assets/{id}`, `model.glb`, `outline`, `PUT tolerance`, `DELETE`, `bulk-delete` | 스캔 GLB 등록(extent 0.05–10m 검증), 외곽선(윤곽·OBB) 서버 계산 |
| 사진 실루엣 | `PUT/GET /assets/{id}/photos[/side.png]` | 방향별 카드 |
| 분리 | `POST /segment` | 바닥/벽/주변 제거 + 사물 분리 + 품질 평가 |
| 패키지 | `POST /packages` | Revit 대체 임포트 (공차/방향 누락 시 422) |
| 작업·관측 | `/inspection-tasks`, `/observations` | 검수 작업·원본 관측 |
| **매칭** | `POST /match` | 후보 자산 순위(자동 확정 여부·유사도) |
| **측정** | `POST /measurements` | 핵심: 자산 지정 또는 `autoMatch`로 서버 정합 → 관측+판정 생성 |
| 결과 | `/inspection-results` | 판정 결과 조회 |
| 증거·보고서 | `/evidence`, `/reports` | 업로드, 한국어 요약 |
| 동기화 | `GET /sync/state`, `/sync/events`(SSE) | 관리자 변경 → 단말 즉시 반영 |
| 로그 | `POST /log` | 앱 로그 수집 |

### 판정 규칙 (`spatial_core.inspection.judgment`)
LOW/UNKNOWN 신뢰도 → **RETAKE** · 확정 초과(편차−불확도>공차) → **FAIL** · 전 항목 확정 내부 + HIGH → **PASS** · 경계 걸침/MEDIUM → **REVIEW**. 기본 공차: 위치 15mm, Z 10mm, 회전 1.0° (자산별 변경 가능).
검수 결과가 FAIL/REVIEW이면 **이슈가 자동 생성**된다(같은 자산에 열린 이슈가 있으면 재측정 이력만 추가).

## 5. 정합·매칭 엔진 (spatial-core + `services/inspection.py`)

### 5.1 정합
- **2단 ICP**: point-to-point(대략) → point-to-plane(정밀). 접선 미끄럼 해결, 1회 약 1~3초.
- **`align_object`**: 관측 점군을 등록 모델에 맞추는 전역 정렬. yaw 격자 × 위치 힌트 후보를 만들어 4자유도(yaw+이동)로 ICP, 잘린(truncated) 점수로 최적 선택, 이후 **point-to-plane 정제**(모델 점의 법선은 PCA 이웃으로 추정 — 앱이 만든 GLB는 점-삼각형이라 삼각형 법선이 무의미).
- 바닥 지지면 추정, 지지면이 불확실하면 보수적으로 처리(`_find_support_plane` 방어 포함).

### 5.2 관측 분리
- `_segment_observation`: 힌트 중심 주변에서 바닥·벽·주변 클러스터를 걷어 내고 사물만 남김. 히스토그램 평활(3탭 컨볼루션)로 안정화.

### 5.3 자동 매칭
1. 관측 크기와 각 자산 크기를 비교해 **크기 페널티** 계산 → 상위 4개 후보 선별.
2. 후보마다 `align_object` 실행 → 인라이어 비율·잔차 점수.
3. 유사도 = 인라이어 × exp(−1.5·크기페널티) × (1−0.5·min(1, 점수/0.6)).
4. 자동 확정 조건: 크기 페널티 한도 이내 **그리고** 인라이어 ≥ 0.50 **그리고** 점수 ≤ 0.50. 아니면 후보 목록을 사용자에게 제시.
5. 부분 관측(보이는 면 58~76%)이어도 모델 일부와의 일치로 판단.

### 5.4 신뢰도·불확도
서버 정합 지표(RMSE·인라이어·점수·추적 상태)로 산출, 기기 보고값보다 우선하며 하드캡 있음. 회전 불확도는 현재 0.5° 고정(GT 보정 대상).

## 6. 통합관리자 웹 (`/admin/`)

바닐라 JS SPA(해시 라우터), 의존 라이브러리 로컬 번들(`vendor`), 3D 뷰어(three.js 계열). 로그인: 사용자명/비밀번호 → 서버 세션 쿠키, 쓰기 요청에 CSRF 헤더(`X-Requested-With: markerless-admin`). 단말에서 변경이 생기면 SSE로 화면이 자동 갱신된다.

### 6.1 역할(권한)
| 기능 | 통합관리자 | 현장관리자 | 검수자 | 열람자 |
|---|:-:|:-:|:-:|:-:|
| 대시보드·자산·검수 이력·3D 조회 | ● | ● | ● | ● |
| 이슈 등록·코멘트·확인·오탐 처리·재검수 요청·종결 | ● | ● | ● | – |
| 조치 지시(담당 배정)·조치 완료·강제 종결 | ● | ● | – | – |
| 자산 정보·공차 수정, 보관/복원, 공간 수정 | ● | ● | – | – |
| 자산 삭제(단건·일괄) | ● | – | – | – |
| 감사 로그·시스템 정보 | ● | ● | – | – |
| 사용자 추가·역할 변경·비밀번호 초기화 | ● | – | – | – |

### 6.2 메뉴별 기능
**운영**
- **대시보드**: KPI(자산·공간·단말·검수 건수·오늘 검수·합격률·열린 이슈·기한 초과·심각 이슈), 기간별(3~90일) 판정 추이 차트, 판정 분포, 이슈 상태·심각도 분포, 불합격 상위 자산, 최근 검수·이슈·관리 활동.
- **검수 이력**: 필터·검색, 판정/신뢰도 배지, 목록 선택 후 **일괄 삭제**, **CSV 내보내기**(UTF-8 BOM), 행 클릭 → **검수 리뷰**.
  - *검수 리뷰*: 3D 뷰어에서 등록 모델·관측 점군·정합 결과 위치를 겹쳐 보고, 판정 근거(reasons)·편차·정합 지표(일치율·잔차)·매칭 방식(지정/자동)·관련 이슈를 확인.
- **이슈·조치**: 칸반 보드/목록, 자동·수동 이슈, 상태 전이 워크플로우(발견 → 확인 → 조치 지시 → 조치 중 → 조치 완료 → 재검수 요청 → 종결, 오탐·무시), 심각도(경미/보통/심각/치명), 담당자·기한, 코멘트·이력 타임라인. 종결은 재검수 PASS가 있어야 하며 없으면 사유 있는 강제 종결(관리자급).

**자산**
- **자산 관리**: 목록(검색·종류/상태 필터·정렬), 일괄 보관/복원/삭제, 자산 상세(3D 뷰어: 표면·점군·외곽선·외곽 박스·치수(mm)·사진 실루엣 레이어 토글, 정보·공차(위치/Z/회전)·메모 수정, 등록 단말·스캔 시각·GPS, 관련 검수·이슈). **검수 표시 레이어 기본값**을 자산별로 지정하거나 전체 자산에 일괄 적용(기본: 외곽선·박스·치수·실루엣 켜짐, 표면·점군 꺼짐).
- **공간**: 공간 목록·이름/층 수정·삭제(월드맵 유무, 자산 수).
- **단말기**: 단말별 등록 자산·검수 건수·마지막 활동.

**시스템**
- **사용자·권한**: 계정 추가, 역할 변경, 활성/비활성, 비밀번호 초기화, 역할별 권한표.
- **감사 로그**: 최근 300건(로그인 성공/실패, 자산 수정·삭제, 이슈 전이, 사용자·비밀번호 변경 등) — 일시·사용자·행위·대상·상세·IP.
- **시스템 설정**: 내 계정(비밀번호 변경), 서비스 정보(외부 주소 복사, 버전·Python, 가동 시간, 저장소 용량, 데이터 건수, 디버그 로그 상태), 역할별 권한표, **개발 내역서 다운로드(이 문서)**.

## 10. 정확도 관련 실측·검증 결과
- 합성 벤치마크 기준 자세 오차 약 1cm(서버 정합 잔차는 mm 수준). 정확도 수치는 **합성 기준**이며 실측 Ground Truth 캠페인은 미실시.
- 점-대-평면 정제로 낮은 시점·키 큰 사물에서 크게 개선, 실제 저장 검수에서는 변화 작음.
- 실기기 확인: 사물 위치가 등록 때와 달라졌을 때 윤곽선이 옆으로 빗나가 보이는 현상은 정상(실제 이동). 같은 위치에서는 잘 맞음(사용자 확인).
- 자동 매칭 벤치마크 기준선: 정답 자동 확정 약 88%, **미등록 사물 오확정 약 63%**(가장 큰 약점, §13).

## 12-B. 디지털 트윈 확장 (2026-10-11 이후 추가분)

> 이 장은 공간 전체 스캔·3D 디지털 트윈 확장을 정리한다. 상세 계약·측정 결과는 `docs/INTERFACES.md`, `docs/QUALITY_TECHNIQUES.md`, `docs/ACCEPTANCE.md`.

### 새 메뉴·화면
- **관리자 웹 → 자산 → 3D 디지털 트윈**: 건물/층/공간 선택, 외부 조망 → 출입문 → 실내 걷기(WASD·터치 조이스틱, 벽 미끄러짐 충돌) → 포털로 방 이동 → 층 전환, 자유 투어, 자동 투어, 사진 모드.
  레이어(실사 텍스처 / 관측 메시 / 추정 INFERRED / 설계 DESIGN / 치환 CAD / 커버리지 히트맵 / 외피)와 불투명도, 미관측 강조(주황 빗금), 단면·천장 숨김, 측정(mm)·핀·캡처.
  벽 두께(BIM/MEASURED/CONFIG_DEFAULT/INFERRED) 편집·승인, 포털 추가·이동·승인, 자산 클릭→기존 자산 상세/이슈/검수 이력.
  품질 선택(자동/높음/보통/낮음), 점진 LOD(mobile→web→full), 텍스처 메모리 예산, 성능 가드.
- **iOS 앱 → ② 스캔·등록 상단 모드**: ① 공간 전체 스캔 / ② 시설물 스캔 / ③ 사물 외관 스캔(기존 그대로). 키프레임(RGB·깊이·신뢰도·포즈) 수집, 커버리지 HUD, 선명도/정지 깊이 평균, 선택형 4K 정지 사진, RoomPlan 구조 패스(별도), 재개 가능한 업로드 큐.
- **시스템 설정**: 개발 내역서 다운로드(이 문서). 기본/임시 비밀번호는 첫 로그인에서 변경 화면이 먼저 뜬다.

### 파이프라인 (서버, `spatial-core/reconstruction`)
프레임(청크 업로드·sha256 검증) → 구간별 세션 정합 → **포즈 그래프(루프 클로저)** → **AI 사람 마스크** → 희소 TSDF 융합 → 마칭큐브 메시 → 구조 추출(바닥·천장·벽·문/창 후보, 면적 커버리지) → **메시 정규화** → UV 아틀라스 + 가시성·노출 보정 텍스처 → LOD → 사물 후보 → 리비전 저장.
출처 구분: OBSERVED(관측) / INFERRED(추정, 주황) / DESIGN / REPLACEMENT. OBSERVED 원본은 덮어쓰지 않고 새 리비전을 만든다. 미관측은 만들어 채우지 않는다(회색+마스크).

### 측정 결과 요약 (합성·공개 RGB-D 기준 — 실기기 아님)
평면 오차 ~1mm, 방 치수 오차 4~5mm, 재방문 5회 면적 드리프트 1.1%, 드리프트 보정(벽 번짐 86.5→5.2mm), 메시 정규화(평면편차 2.8→1.0mm), 노출 변동 텍스처 얼룩 −24%, 사람 유령 4.24→0㎡.
**기각**: RGB 가이드 업샘플, AI 단안 깊이 채우기(LiDAR 범위 안 7.4% > 단순 최근접 5.8%), 프레임-모델 자세 보정.

### 안전 장치
자동 확정 없음(사물→자산은 후보 제안), 미확정 CAD(UNDETERMINED)는 근거+명시 확인 없이는 승인 불가, 대칭·모호 정렬은 거부, 월드맵 재위치 실패 세션(UNREGISTERED)은 자동 병합 금지, 비밀번호 정책·강제 변경, 신규 API 입력 방어.

### 남은 과제
실기기·실측(GROUND_TRUTH.md), 모바일 단말별 토큰, PostgreSQL, 재구성 워커 분리, 개인정보 마스킹, 멀티밴드 텍스처, 거울/유리 처리 검증, git 이력 — `docs/PRODUCTION_GAP.md`.

## 13. 추가 고도화 후보 (우선순위 제안)

### A. 매칭 신뢰성 (최우선)
1. **3단계 판정**: 자동 확정 / 후보 제시 / 미등록 거부. 미등록 오확정률을 ~0%로 낮추면서 자동 확정률 ≥ 88% 유지.
2. **치수·각도 서명 비교**: "관측 치수 ≥ 보이는 면 치수" 논리로 부분 관측 보정, 길이·높이·폭·각도 일치도를 점수화(실제 BIM/CAD 치수 기준 매칭에 대비).
3. 1위–2위 **마진** 사용, `modelCoverage` 반영, 후보 풀 확대(거친 정렬 → 정밀 정렬).
4. 앱 후보 선택 UX 개선(유사도·치수 차이·3D 미리보기), 관리자 **매칭 진단 화면**(왜 이 자산이 선택/거부됐는지, 오확정 신고 → 임계값 튜닝 데이터).
5. 사용자 선택 결과를 로그로 쌓아 **임계값 자동 보정**(온라인 학습).

### B. 정렬·판정 정확도
1. **Ground Truth 캠페인**(실측 줄자/토탈스테이션) → 불확도 모델 회귀, REVIEW→PASS 전환율 개선.
2. 카메라 위치(`cameraPositions`) 서버 반영으로 가시 면 기반 가려짐(occlusion) 처리 → 부분 관측 모호성 감소.
3. 다중 프레임/다중 측정 융합(시간 평균·이상치 제거), 대칭 사물용 비대칭 단서(텍스처·사진 카드) 활용.
4. 월드맵 복원 품질 지표 노출, 환경 변화(가구 이동) 시 자동 재앵커링.

### C. 앱 UX/기능
1. 오프라인 큐(측정·사진 업로드 재시도), 저장 실패 복구.
